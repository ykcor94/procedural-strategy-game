# Geographic stage contracts

Civilization products, authoritative ownership grids, vector borders and independent regeneration are documented in [CIVILIZATION.md](CIVILIZATION.md).

The society extension keeps `province`, independent language/religion majorities and minorities, per-cell output/productivity/trade access, routed city links, national technology/currencies and calendars in simulation data. `civilization/society.js` coordinates geographic province repair, economy/trade, religious fronts and mixed-cohort census modules. Presentation tiles never own these entities. Rendering applies category masks to the same physical LOD land/lake mask, while world-scale ownership remains authoritative. Rivers retain actual terminal cells and the renderer trims only against that shared refined shoreline. Expensive trade searches run on explicit dependent regeneration; moved hubs repair affected paths with a cached-source search, and ordinary identity changes reuse the network.

World: `{version,width,height,seed,settings,name,layers,meta}`. All rasters in `layers` are typed arrays of width*height. Monthly temperature/precipitation are month-major (`m*N+i`), always 12 months, January = 0. Elevation meters above fixed sea level 0, land is > 0, ocean <= 0. Latitude +90 at top; x wraps; y never wraps. Settings defaults in src/core/settings.js. Modules use `.js` extensions.

Stage exports: `generateTerrain(world,ctx)`, `generateClimate(world,ctx)`, `classifyClimate(world)`, `deriveBiomes(world)`, `generateHydrology(world,ctx)`. They mutate world.layers and world.meta. They may return promises. ctx.report(stage,fraction,message) sends progress. Terrain module writes elevation and baseElevation (independent copies), plus optional typed supporting layers. Climate writes temperature, precipitation (month-major), annualTemperature, annualPrecipitation, soilMoisture and koppen. Hydrology writes flow, flowTo (Int32, -1 outlets), basin (Int32), lake (Uint8), river (Uint8), filledElevation and optional lakeDepth. Biome after hydrology writes biome. Optional arrays all in layers.

Climate registry: export KOPPEN from src/data/climates.js as ordered array objects `{id,code,name,color,description}`. 0 = ocean. Biome registry: BIOMES from src/data/biomes.js same objects, code optional. Functions resolve numeric IDs. Data must stay separate from rendering.

`src/core` owns coordinates, settings, typed-layer metadata and invalidation. `src/generation` owns deterministic global products and the worker pipeline. `src/render` composites global cached maps, visible LOD terrain and shared river vectors; `src/lod` owns disposable visual tiles and sparse detail sampling. `src/editor` distinguishes global raster edits from normalized visual strokes. `src/persistence` restores complete arrays and versioned detail metadata. No simulation entity data belongs in terrain tiles.

Ocean ice is a separate surface product: `seaIce` is month-major Uint8 coverage (0–255), `annualIce` is mean coverage and `permanentIce` is minimum monthly coverage. `warmestTemperature` supports continuous physical snow rendering. Ice never changes land masks or ocean Köppen IDs. `riverDistance`, `tectonicRift` and `crustAge` are derived/support fields. Flow accumulation is in m³/s.

Saves use world schema 3 inside the ATLAS2 binary container. New `.atlas` files use a binary manifest and aligned array bytes; version-1 JSON and version-2 JSON/binary imports preserve terrain/climate/drainage while deriving surface moisture and landmass IDs. Imports validate registered array types and adjacent, downhill, acyclic routing. Visual terrain is reproducible from global arrays, the `meta.detail.algorithm` identifier and sparse world-space strokes, without storing a planet-wide fine raster. See LOD.md for hierarchy and invalidation contracts.

The `surface` stage runs after hydrology. It writes Float32 `naturalMoisture`, `riparianMoisture`, `alluvium`, `floodplainFraction`, and `surfaceMoisture`. Only the final surface/biome products depend on `riverFertility`; monthly rainfall, runoff and discharge do not. The climate stage computes rain-fed soil directly at each final grid cell, avoiding ocean-to-land moisture interpolation. `landmass` is an Int32 connected-component ID (0 ocean); metadata stores area-weighted continent/island records. `volcanicUplift` is a terrain support field in meters.

`ui/units.js` owns presentation conversions and the browser preference. All generator settings, typed layers, brush strengths and file data remain SI. Absolute and difference temperatures have distinct conversion functions. Elevation controls retain exact canonical values across preference changes, including unsaved input.

Generation algorithm 5 uses seed-varied plate layouts, smooth contributor weights, curved mountain families and independently seeded broad highland provinces. Optional Float32 `mountainUplift`/`highlandUplift` record potential contributions in meters. Their metadata coordinates are normalized to the displayed, rotated world. Continent targets support 1–10 cores, finite marine buffers and a smooth polar taper; these constraints never determine height magnitudes. Large-grid refinement uses a signed coast contour with separate land/sea interpolation to preserve narrow straits.

Visual performance is separate from the save schema (still 3). Workers start on demand, stream small parent previews, cache geographic height/shade/symbol planes and transfer ImageBitmaps. The main renderer composites cached lighting and coast paths, so view toggles cannot invalidate terrain. `render/relief.js` shares macro lighting with refined tiles. Gradient-window and direct noise paths are numerically identical. See LOD.md for memory budgets, keys and invalidation margins.

Civilization metadata lives in `meta.civilization`; authoritative cell ownership, provinces, culture/language/religion majorities and minorities, population, habitability, productivity, economic output and trade access are registered global layers. Civilization generation runs separately from physical generation. Country budgets combine geographic potential with seeded demographic variation; regional urban allocation conserves residents and reserves provincial seats. Province repairs preserve sovereignty, merge tiny generated fragments and retain deliberately painted divisions. Identity changes avoid expensive geographic regeneration. Imports normalize legacy metadata without redistributing saved inhabitants.

`src/game/state.js` owns optional version-1 campaign metadata under `meta.game`: player nation, starting/current date, fractional elapsed hours, pause state, five-speed index and saved map view. Advancement only changes that clock. `ui/game.js` owns generator/selection/game presentation, filtered nation cards, wrapped homeland fitting, read-only inspection and pause/menu controls. Civilization mutation functions and physical generation/history handlers enforce the read-only state independently of hidden controls. Campaign metadata is validated on import; orphan/invalid sessions are discarded while retaining the world. Browser visibility pauses play, and imported campaigns resume paused.

No Religion uses sparse religion and family ID65534 with `secular:true`, no homeland and no holy cities. It is optional and does not consume founded-religion counts. Existing majority/minority arrays and city cohorts carry its shares, avoiding another global raster. Censuses expose noReligionShare and conserve total inhabitants. Shared faith families normally retain a common theology. Economic language refresh is a callback from the civilization coordinator after profiles/routes are available, only during all/culture generation; this avoids module cycles and preserves scope independence.

Political and cultural maps share physical LOD masks. Visual nearest-land attribution covers refined islets while the ownership raster remains unchanged. Province lines use the wrapped shared-cell border graph, never artificial closures of clipped fill polygons. City plans are cached world-space vector scenes: population controls footprint and complexity; connected outskirts begin at 100,000 residents and clip to refined land. Visible terrain tiles are pinned within a bounded cache allowance; sharper cached children cover zoom transitions, then fade into the requested LOD while remaining cached.

`ui/map-probe.js` reads authoritative numeric statistics for middle-click popups; it also owns the layer-bar disclosure. Inspector history is independent of mutation undo/redo. Numeric provincial atlases and national economic totals share renderer palette helpers with their legends. Trade routes retain cost-distance paths; rendering classifies each visible segment as sea, channel or land rather than coloring a whole mixed journey as maritime. Only actual hydrological channels grant reduced river travel costs. Language normalization reconciles inherited lexicons and affixes with declared sound inventories; regional language contact uses bounded cost-distance fronts rather than a cell-by-cell coastal replacement mask.

## Version 9 contracts

- **Campaign economy** (`src/game/economy/`). `model.js` derives the unsaved baseline (`buildRuntime`: places = settlements plus each province's countryside, with industries, jobs, site fit and routes) and aggregates law effects; `evaluate.js` turns saved state into live output, revenue, spending, stability and build capacity (pure; `over` replaces fields for what-if previews); `sim.js` owns creation, the day/month/year ticks and every player action; `validate.js` checks saved state. Data lives in `src/data/{industries,buildings,laws,initiatives}.js`.
- **Partition invariant.** At campaign start the sum of industry outputs in a place equals its generated output, and the nation's total equals `nation.economicOutput`. Law effects are stored relative to the starting positions, so a new campaign begins exactly at the generated economy. The generator layers and `meta.civilization` are never written during play.
- **Time.** `advanceGame` still only moves the clock; `advanceEconomy` catches the economy up to `floor(elapsedHours/24)`, one day at a time (construction), with month (ledger, growth, reforms, stability) and year (snapshot) steps on the 1st. State is plain JSON in `meta.game.economy`; `GAME_VERSION` is 2 and v1 campaigns upgrade on load. A damaged economy block is dropped without losing the campaign.
- **Baseline cache.** `runtime(world,econ)` caches per economy and is rebuilt when `civ.revision`, `civ.tradeRevision` or surveys change; buildings in vanished places are ignored.
- **UI.** `ui/ministry.js` owns the header strip, the panel and the keys; each tab module exports `render(ctx)`, `handlers` (`data-act`) and `inputs` (`data-input`). `ui/economy-card.js` renders the industry breakdown in entity panels and uses a provider set by the ministry for live figures.

## Version 8 contracts

- **Territory display geometry** (`render/territory-geometry.js`). Every boundary between two grid regions is one shared chain between junction vertices (degree ≠ 2, diagonal pinches, the wrap seam). Chains are corner-cut once (endpoints pinned, displacement ≤ ~0.35 cell), and fill rings and border strokes reference the same chains, so neighbouring fills meet exactly. LOD simplification is per chain in half-octave bands. The authoritative grid and the raw `extractTerritories`/`buildBorderPaths` helpers are unchanged.
- **LOD compositing.** Tile rectangles snap to device pixels (`snapRect` in `lod/tile-manager.js`) so the land mask has no partial-alpha seams; `visibleTiles` takes the previous level for hysteresis; pinned tiles are evicted only above twice the cache budget.
- **Natural borders.** `naturalBarriers` (generator) derives crest, drainage-divide and river barrier fields; `naturalBarrier(world,geo,i,j,dx,dy)` is the edge cost used by expansion and by `relaxBorders`, a bounded pass (±10% area, simple-point connectivity, fixed centres) that moves frontiers onto barriers.
- **Population.** `carryingDensity(world,i)` is the potential density per cell. National budgets are capacity × a bounded, regionally correlated multiplier, water-filled between a floor and ceiling of capacity; `nation.carryingCapacity` and `nation.populationHistory` are stored. Economy uses `economicProfile.landPressure` for crowding.
- **Cities.** `city.footprint` is `[cell,count,…]` (core first) and sums to `city.population`; read it through `cityFootprint(city)` (society-utils), which falls back to the core cell for older saves. `nation.urbanBias` is a stable national tradition; `settings.urbanizationVariation` scales it.
- **Trade.** Hubs are tiered (gateways by farthest-point sampling, each nation's main city, regional centres); routes carry `tier`. `tradeGravity`/`tradeVolume` are exported and shared with reweighting.
- **Languages.** `phonology.archetype`/`style` name the sound archetype; optional `codas`, `weights`, `harmony`, `placeSuffixes`, `nationSuffixes`, `familyPrefixes` and `glue` are normalized with the inventory. `settings.accentedLetters` (default on) controls accented graphemes at generation time.
- **No Religion.** Shares come from a blurred national propensity field with low-frequency regional variation, calibrated so `noReligionRate` is the typical world share at reference development; development and cities shift it locally.
- **UI.** Styles live in `styles/` (tokens, base, layout, components, panels, views); themes redefine tokens only. `ui/workspace.js` owns settings search, the shortcuts dialog and global keys. Element ids, form `name`s and `data-*` hooks are the stable contract used by the modules and the browser tests.
